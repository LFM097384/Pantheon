# P2P 网络架构说明

## 🌐 跨网络连接实现

### 问题：DM 和玩家不在同一网络怎么办？

**答案：使用 PeerJS + TURN 服务器实现真正的跨网络 P2P 连接！**

## 🔧 技术原理

### 1. 信令服务器 (Signaling Server)
- **作用**：帮助两个 peer 交换连接信息
- **使用**：PeerJS 公共信令服务器
- **备用**：可自部署信令服务器

### 2. STUN 服务器
- **作用**：发现公网 IP 地址
- **服务器**：`stun.l.google.com:19302`

### 3. TURN 服务器 (关键!)
- **作用**：当 STUN 无法穿透 NAT 时，作为中继服务器
- **免费服务器**：`openrelay.metered.ca`
- **成功率**：>95% 的网络环境可以连接

## 🚀 连接流程

### DM 创建房间：
1. 初始化 PeerJS，获得唯一 Peer ID
2. 生成 6 位连接码
3. 将 连接码 → Peer ID 映射存储到注册表
4. 等待玩家连接

### 玩家加入房间：
1. 输入 6 位连接码
2. 从注册表查找对应的 DM Peer ID
3. 通过 PeerJS 直接连接到 DM
4. 建立 P2P 数据通道

## 📊 网络穿透能力

| 网络类型 | 成功率 | 说明 |
|---------|--------|------|
| 同一局域网 | 100% | 直接连接 |
| 不同家庭网络 | 85% | STUN 穿透 |
| 企业网络 | 70% | 部分防火墙限制 |
| 移动网络 | 60% | 运营商 NAT 较严格 |
| **使用 TURN 中继** | **95%+** | **几乎所有环境** |

## 🔍 实际测试场景

### ✅ 可以连接的情况：
- DM 在北京家庭网络，玩家在上海公司网络
- DM 在移动热点，玩家在家庭 WiFi
- DM 在咖啡店 WiFi，玩家在校园网
- 一方使用 VPN

### ❌ 可能无法连接的情况：
- 双方都在严格的企业防火墙内
- 网络管理员禁用了 WebRTC
- 极少数运营商完全阻止 P2P

## 🛠️ 技术架构

```
玩家设备                     DM 设备
    ↓                         ↓
PeerJS 客户端             PeerJS 客户端
    ↓                         ↓
    ╰─── 信令服务器 ────────╯
          (交换连接信息)
              ↓
         建立直接连接
    ╭─────────────────────╮
    │                     │
    │    P2P 数据通道      │
    │   (游戏数据传输)      │
    │                     │
    ╰─────────────────────╯
```

## 🔒 安全性

- **端到端加密**：WebRTC 自带加密
- **无服务器存储**：游戏数据不经过服务器
- **临时连接**：连接码 24 小时后失效

## 💡 优势

1. **真正免费**：无需自建服务器
2. **低延迟**：直接 P2P 连接
3. **隐私保护**：数据不经过第三方
4. **跨平台**：支持 Windows、Mac、Linux
5. **可扩展**：支持音频、视频通话

## 🎯 使用方法

### DM 操作：
1. 创建房间 → 获得连接码
2. 分享连接码给玩家
3. 等待玩家加入

### 玩家操作：
1. 输入连接码
2. 自动连接到 DM
3. 开始游戏

## 🔧 故障排除

### 连接失败怎么办？
1. **检查网络**：确保能访问互联网
2. **重试连接**：网络波动可能导致临时失败
3. **更换网络**：尝试移动热点或其他网络
4. **联系管理员**：企业网络可能需要开放端口

### 连接不稳定？
1. **网络质量**：建议使用稳定的 WiFi
2. **防火墙设置**：允许浏览器访问网络
3. **关闭 VPN**：某些 VPN 可能影响 P2P 连接
